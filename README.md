# is · 事情们

一个不需要账号的私人 PWA 数字相册。

## 运行

在本目录执行 `python3 -m http.server 8000`，然后访问 http://localhost:8000 。

本地测试可在 localhost 使用。iPhone 安装 PWA 需要将这些静态文件部署到 HTTPS 网站（例如免费的 GitHub Pages），不可直接从下载的 HTML 文件获得完整 PWA 功能。

## 备份

内容在 IndexedDB 中，不会自动同步。点击右上角 `···` →「导出完整备份」，将生成的 `.json` 文件保存到 iCloud Drive/事情们。该文件包含所有照片的原始二进制内容（以 base64 编码）及文字。可在另一设备用「从备份恢复」合并。数据量很大时，JSON 备份可能占用大量内存，建议分批存档并保留多个备份版本。

## iPhone 分享

iOS Safari 不保证将 PWA 注册为系统分享目标。可用快捷指令「接收共享表单中的图像」→「存储文件」→ iCloud Drive/事情们/收件箱；再在 is 的 + 中从「文件」选择照片。文字可用快捷指令「URL 编码」→「打开 URL」跳转到 `https://你的域名/?text=编码后的文本`，打开 is 的文字编辑器，手动确认保存。分享的图片不会自动进入相册数据库；这属于第一版限制。

## 隐私与限制

不含服务器、统计或第三方脚本。没有自动 iCloud 同步；同一个网址在不同设备上是不同的本地数据库。删除浏览器网站数据可能永久丢失未备份内容。

## v0.2 · Windows 98 与观看深度

- 首页保持双列独立瀑布流；每张卡片的高度由内容决定，显示深蓝标题栏、经典灰色立体边框。
- 点击卡片进入内容观看（第 1 层），底部只有「确定」。轻点退出一层；按住约 500 毫秒深入一层：内容观看 → 信息查看 → 信息编辑。第三层长按不执行操作。
- 信息编辑的标题、备注在轻点「确定」时写入原有 IndexedDB 数据库；失败时停留编辑层并保留输入。已有记录不需要迁移，旧备份仍可恢复，v0.2.2 新备份包含标题与备注。
- 键盘可用 Alt+Enter 或方向右键深入，Escape 返回。为保持观看界面单按钮，删除移至首页 `···` → 管理与删除内容。
- 分享与 iCloud 限制仍与 v0.1 相同，未实现自动同步。

## 更新 GitHub Pages

将本目录内的 `index.html`、`app.js`、`style.css`、`sw.js`、`manifest.webmanifest`、`icon.svg` 上传到仓库根目录，覆盖同名文件。若浏览器缓存旧版，请刷新或关闭重新打开 PWA。更新代码不应删除同一网址/同一浏览器下的 IndexedDB 数据，但请先导出备份。

## v0.2.2（2026-11-06）

- 图片观看层单独持有 Object URL，跨信息层、编辑层及保存过程保持有效，关闭后释放；瀑布流先卸载旧节点再释放其 URL，再为新节点建立 URL。
- 去掉默认「生活照片」alt 文本；有用户标题时用标题描述图片，卡片按钮仍有可访问名称。
- 添加入口为固定右下角蓝色圆形白色加号，使用 iPhone 安全区边距，页面底部留出空间。
- 文字编辑标题与正文，图片编辑标题与备注。文字沿用 text 字段；旧 notes 字段原样保留，不自动覆盖正文。数据库名称、版本和记录编号不变，无迁移及清空操作。
- Win98 按钮使用统一的 focus-visible 内圈虚线规则；键盘操作显示焦点反馈。
- 修正图片备份遗漏 filename/title/notes 的问题。仍为 is-backup / version: 1，恢复逻辑兼容旧文件；旧备份中原本缺失的元数据无法补回。
- Service Worker 缓存更新为 is-static-v022；仅清理本应用静态缓存，不修改 IndexedDB。
- 设置面板显示 v0.2.2，便于确认更新。

## 诊断与验证边界

已确认「生活照片」来自 app.js 的默认 alt。仓库 HEAD 31e96f4 已经取消旧的 renderUrls 回收，改成按记录 ID / Blob 身份缓存；IndexedDB 每次读取生成不同 Blob 对象，造成重复 URL 及资源积累。该缓存还被观看层与瀑布流共用，缺少明确的所有权及回收边界。v0.2.2 改为分离资源所有权。

没有在云端重现用户报告的 iPhone 偶发问号，所以不能断言资源积累是唯一根因，也不能据此宣称 iPhone 问题已彻底修复。若实机仍出现，需要记录 iOS 版本、图片类型/尺寸、编辑次数、后台切换情况后继续定位。

通过的检查：

- node --check app.js / sw.js，git diff --check。
- node tests/regression.cjs：模拟 DOM / 存储，50 次图片编辑后的 URL 生命周期及数量、图片原始字节保留、旧文字正文编辑与旧 notes 保留、保存失败留在编辑层、备份 v1 元数据与图片解码。
- 云端 Chromium：Input 添加文字、标题及正文编辑、四层键盘深入与短按返回、图片导入与连续 10 次编辑、观看层及瀑布流 naturalWidth=400、刷新后本地数据保留、完整备份导出与合并恢复无重复、图片标题备注恢复。
- 云端浏览器测试完成后仅增加编辑标签的 htmlFor 关联及设置版本标记，已重新执行语法与回归检查。

待 iPhone 实机验收：

1. 原有照片连续修改标题/备注至少 10 次，每次回到观看层及瀑布流；检查问号、后台切回及重启后显示。
2. 旧文字卡编辑正文并返回两层；确认旧卡片、标题及文字均在。
3. 长按 500ms 深入，短按返回；iOS 键盘收起后仍能正常操作，确定按钮样式一致。
4. 滚动长瀑布流、横竖屏、主屏幕独立运行时，加号始终可见且避开 Home 指示条。
5. 新增后自动滚动、关闭重开近期定位；旧内容在上、新内容在下。
6. 原快捷指令 → iCloud Drive/itissomething → is 选择文件导入；JSON 备份保存至 iCloud Drive 并恢复。
7. 从原 v0.2.1 地址更新后仍可离线启动，旧数据存在，设置显示 v0.2.2。

## GitHub 更新步骤（网页）

1. 在 iPhone 原 is 中先导出一份完整备份。
2. 解压 is-app-v0.2.2.zip，打开 mimicrisis/Is 仓库，选择原 GitHub Pages 发布分支，使用 Add file → Upload files。
3. 上传包内 index.html、app.js、style.css、sw.js、manifest.webmanifest、icon.svg，覆盖根目录同名文件。不要上传外层文件夹或 ZIP 本身。README.md 及 tests/ 可同时更新，或只上传运行所需六个文件。
4. 提交信息填写 Release v0.2.2。保持 Settings → Pages 原来的分支和目录配置，等待部署完成。
5. 在 iPhone Safari 打开原相册网址，刷新；完全关闭原主屏幕 is 再打开。如果首次仍显示旧版，再关闭并重开一次；在 ··· 中确认 v0.2.2。
6. 沿用原网址和主屏幕图标。不要清除网站数据、不要卸载 PWA，也不要更改 Pages 路径。

压缩包包含测试代码和说明；静态 PWA 无依赖安装或构建步骤，六个运行文件即可部署。
